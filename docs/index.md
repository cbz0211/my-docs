# 我的技术文档

欢迎访问我的个人文档网站。本站用 Markdown 编写内容，由 MkDocs Material 生成静态页面，再通过 GitHub Actions 自动部署到 GitHub Pages。

在这次实践里，我完整走了一遍「写文档 → 本地构建 → 推送 → 自动构建 → 自动发布」的链路，也第一次学着读 Actions 日志定位问题：文档目录放错位置、严格模式下链接警告导致构建中止，都是靠日志里的 `ERROR` 和 `WARNING` 行找到原因的。把源码、构建产物、工作流和托管网站分开之后，才明白为什么生成的 `site/` 不需要手工维护。

> 小结：仓库里只需要维护 `docs/` 下的源码和几个配置文件；`site/` 由工作流在云端生成，仓库中看不到它，但它最终就是网站上显示的内容。
